# TAP Standings

> **Live multi-sport standings dashboard for University of North Dakota athletics.**
> Automatically scraped and deployed every morning at 9:00 AM CT via GitHub Actions.

🔗 **[View Live Site](https://kcakins1120.github.io/TAP_Standings/)**
📄 **[View Raw JSON Data](https://kcakins1120.github.io/TAP_Standings/data.json)**

---

## 📋 Overview

TAP Standings is a fully automated, serverless standings dashboard that pulls live conference standings from multiple athletic associations relevant to UND and displays them on a clean, dark-themed web page — no backend, no database, no manual updates required.

Standings are scraped using a headless Chromium browser (Playwright), structured into a single `data.json` file, and served as a static GitHub Pages site. The entire pipeline runs on a daily cron schedule inside GitHub Actions.

## ⚙️ How It Works

```
GitHub Actions (cron: 9am CT)
        │
        ▼
scraper/scrape.py
  └── Launches headless Chromium (Playwright)
  └── Visits each standings URL
  └── Waits for JS-rendered table
  └── Parses: Team, Acronym, Conf W-L, Overall W-L, CPTS/PTS (where applicable)
  └── Writes docs/data.json
        │
        ▼
GitHub Actions commits data.json → pushes to main
        │
        ▼
GitHub Pages serves docs/ as static site
        │
        ▼
index.html fetches data.json at page load → renders all standings tables
```

### Key Design Decisions

- **Single browser session** — all 9 sport pages are fetched in one Playwright Chromium instance to minimize CI runtime and resource usage.
- **Stale data fallback** — if any individual sport fails to scrape, the last known good data is preserved in `data.json` and marked `"stale"` so the site never goes blank.
- **No Jekyll** — a `.nojekyll` file in `docs/` tells GitHub Pages to serve files directly without processing them through Jekyll.
- **WSOC pod table skip** — Women's Soccer uses a pod-based format mid-season; the scraper detects and skips pod sub-tables and pulls the full 8-team standings table instead.

## 📊 Data Format (`data.json`)

```json
{
  "generated_at": "2026-10-25T14:00:00Z",
  "sports": {
    "wvball": {
      "id": "wvball",
      "name": "Summit League Women's Volleyball",
      "status": "ok",
      "updated_at": "2026-10-25T14:00:00Z",
      "rows": [
        {
          "rank": 1,
          "team": "North Dakota",
          "acronym": "UND",
          "conf": "8-0",
          "ovr": "18-2"
        }
      ]
    },
    "msoc": {
      "rows": [
        { "rank": 1, "team": "North Dakota", "acronym": "UND", "conf": "5-1", "ovr": "9-3", "cpts": "15" }
      ]
    },
    "mhockey": {
      "rows": [
        { "rank": 1, "team": "North Dakota", "acronym": "UND", "conf": "6-2", "ovr": "10-4", "pts": "18" }
      ]
    }
  }
}
```

**Special columns:**
- `cpts` — Conference points (Men's Soccer, Women's Soccer)
- `pts` — League points (NCHC Men's Ice Hockey)
- `acronym` — Standardized team abbreviation (e.g., `UND`, `NDSU`, `USD`)

## 🚀 Setup & Deployment

### Prerequisites
- GitHub account
- Public repository (required for free GitHub Pages)

### First-Time Setup

1. **Fork or clone** this repository under your GitHub account.
2. **Enable GitHub Pages:**
   - Go to **Settings → Pages**
   - Set Source to **GitHub Actions**
3. **Trigger the first run manually:**
   - Go to **Actions → Update data and deploy site → Run workflow**
4. Your site will be live at:
   ```
   https://<your-username>.github.io/TAP_Standings/
   ```

### Schedule
The workflow runs automatically at **`0 14 * * *` (UTC)** — equivalent to **9:00 AM CDT / 10:00 AM CST**.

To trigger a manual refresh at any time: **Actions → Update data and deploy site → Run workflow**

## 🛠️ Dependencies

```
playwright==1.44.0
beautifulsoup4==4.12.3
requests==2.32.3
lxml==5.2.2
```

Install locally:
```bash
pip install -r requirements.txt
python -m playwright install chromium
```

Run the scraper locally:
```bash
python scraper/scrape.py --out docs/data.json
```

---

## 📝 Notes

- `docs/data.json` is committed back to the repo by the GitHub Actions bot after each successful scrape — this is intentional and expected.
- The `docs/` folder is the GitHub Pages publish directory. Do **not** rename it without updating `update.yml`.
- The `.nojekyll` file in `docs/` is required — without it, GitHub Pages will attempt a Jekyll build and fail.
